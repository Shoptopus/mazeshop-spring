# Raspberry Pi hosting and releases

For current Mazeshop Stripe TEST configuration and the exact public signed-webhook exception, read [checkout-reliability.md](checkout-reliability.md). It supersedes earlier payment-disabled/checkout-blocker observations in this hosting baseline.

Read `ops/raspberry-pi/README.md` in the project checkout for the installed design and operational procedures. The scripts under that directory and `.github/workflows/pi-release.yml` are the editable sources. Private host audits, credentials, recovery keys and AWS access keys belong outside the public repository.

The deployment repository is `Shoptopus/mazeshop-spring` (a separate public copy; the original repository stays private). GitHub-hosted runners build and test with Java 21, publish the existing tracked React bundles inside the JAR, and produce a signed provenance bundle. The Pi polls public releases and verifies the exact repository, workflow identity, main ref and source digest before running the JAR as the unprivileged application user. It does not run a self-hosted GitHub runner or expose deployment SSH publicly. Do not weaken provenance checks to fix a failing deployment. Only the selected public deployment repository may publish builds; keep the verifier repository and exact certificate identity aligned with its `pi-release.yml` workflow on main. Inspect the latest Actions run before assuming deployment succeeded.

The app binds to loopback behind Apache HTTPS. On 6 November 2026 the owner requested public shop access and the Apache preview gate was removed. Do not re-enable it from older setup notes. The storefront and admin login UI are public; application authentication still protects customer/admin APIs. HTTPS, management-route denial and capability-safe logging remain. The exact `/privacy-policy` route (optional trailing slash) remains public for the standalone legal notice and Google OAuth branding.

The deployed configuration sets `APP_SNAPSHOT_MAINTENANCE_ENABLED=false`. The built-in snapshot job backs up only the main DB and then purges logs; leave it disabled when relying on the external backup. External nightly backups briefly stop the app, capture main DB, logs DB, media and configuration, resume the app, then copy the consistent snapshot to private encrypted versioned S3 storage. Weekly integrity checks prune unused data. Restore tests use disposable databases and the custom Flyway tables `flyway_schema_history_main` and `flyway_schema_history_logs`. Never test recovery against live databases.

On Raspberry Pi, configured systemd memory limits are ineffective until the memory cgroup controller is enabled at boot; verify actual `MemoryCurrent`. Preserve unrelated services on this shared host, and check their recovery during any authorized reboot. An application-only deployment does not need to reboot the host or update unrelated containers.

Preserve the distinction between four historical Etsy prices, 99 working estimates and provisional made-to-order capacity. Use the importer’s `--catalogue-only` mode for product changes; preserve shop settings and CMS pages.
